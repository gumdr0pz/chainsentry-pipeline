# ChainSentry — Market Pipeline

**Program repo for ChainSentry go-to-market.** Owner: Hadri (accountable) · Prepared/maintained: Vesper · Status: **P0 Foundation in flight** (program wk1 = w/c 2026-10-06).

ChainSentry = sovereign, on-prem blockchain forensics + E-KYC for states and regulated entities the US-cloud incumbents price out or can't serve. Doctrine is fixed: **we never sell "cheaper Chainalysis" — we sell jurisdiction-deployable, auditable, Gulf/SEA/BRICS-corridor coverage.** (`strategy/STRATEGY.md` is the doctrine of record.)

This repo holds the execution layer: strategy, activation plan, target rosters, contact intelligence, hiring signal scans, evidence snapshots, and the hiring spec. The CognitiveOS register (private, separate) holds the governed records (OPP/ACT/INT/RSK family) this repo points to.

## Standing rules (non-negotiable)

- **Gates:** outreach mass-sends stay behind G2 (demo-able Reactor/CSV import). Inbound demand handled under Gate-Exception Protocol: methodology + recorded output only, no live demo pre-G2.
- **Sourcing:** every name in this repo carries a dated source or an explicit stale-flag / `none published`. A wrong name is worse than none — new contact data enters via verified passes only, never inferred patterns.
- **Entity hygiene:** name collisions resolved at primary source before use (precedent: MX Global Ltd/MEXC ≠ MX Global Sdn Bhd, cleared 10-Oct at vara.ae).
- **Kill discipline:** dead targets stay in the roster marked KILLED with dates (Tokenize MY-08, Zetrix MY-11) so nobody re-approaches.
- **Positioning:** sell deployability + corridor coverage + auditability — never price.
- **Register sync:** repo changes that move opportunity state get mirrored to CognitiveOS as candidate records; nothing is "merged" without explicit MERGE.
